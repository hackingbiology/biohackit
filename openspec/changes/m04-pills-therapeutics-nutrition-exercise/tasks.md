# M04 Tasks

Ordering: groups with no new dependency first. Each TG is one implementer run (~60 tool calls). Scan decisions are in `docs/ecosystem/m04-pills-therapeutics-nutrition-exercise.md`. "Req" names a requirement in `openspec/specs/<capability>/spec.md` (main) or in this change's deltas (M04). No group seeds a dose, range, MET value, TDEE factor, food composition value, code or constraint without a cited source; a row without one is not written. No group adds a dependency except where it names one and its blocker.

## TG1 — Spec (this change)
- [x] proposal.md, tasks.md, spec deltas written; questions Q150–Q154 appended to docs/QUESTIONS.md; the scan is cited by section (a)–(g).

## TG-a — Typed cadence (no new dependency)
- [x] Typed cadence value (mode, times per day, days of week, interval in days) shared by intakes and therapy sessions, with a pure function that returns due dates. Req: M04 pills "Intake cadence is typed"; M04 therapeutics "Therapy sessions follow a typed cadence". Scan (b). No recurrence library (python-dateutil stays learn-from only). Scenarios: `pills-management::every-second-day`, `therapeutics-management::weekly-sessions`.

## TG-b — Adherence state storage (no new dependency)
- [ ] One stored state per event (`done`, `partial`, `skipped`, `missed`, or none), set only by the user. Req: M04 daily-log "Adherence states have one stored name each". Names mapped per Q150. Scenario: `daily-log-and-adherence::a-pending-event-has-no-state`. Depends on: M05 for the screen; the model is here.

## TG-c — Deterministic daily allocation without a solver (no new dependency)
- [ ] Allocation of intakes into slots by a plain deterministic method; every separation names its constraint; an unsourced constraint is listed and not enforced; a meal has fat only when declared. Req: main pills "Daily intake schedule across slots", "Meal timing and absorption requirements", "Spacing and distance rules"(all three MODIFIED in the pills delta). Scenarios: `pills-management::same-input-same-schedule`, `pills-management::unsourced-constraint-is-listed-not-enforced`, `pills-management::no-constraint-is-seeded`, `pills-management::no-meal-marked-as-containing-fat`, `pills-management::fat-soluble-compound-with-a-fatty-meal`. No constraint is seeded (Q154).

## TG-e — Daily schedule, grouping and in-app reminders (no new dependency)
- [ ] Resolved schedule surfaced to the daily log data with dose and slot, grouped by slot or meal for 60–130 intakes a day; an in-app reminder for an unmarked due intake or session; no push, no email. Req: main pills "Scale to high-volume regimens", "Feeds the daily log and calendar"; main therapeutics "Schedule therapy sessions on the calendar"; M04 daily-log "Reminders are shown in the app first". Scenario: `daily-log-and-adherence::intake-reminder-appears-in-the-app`, `daily-log-and-adherence::due-session-appears-in-the-app`. Reminder channels beyond in-app are blocked by Q144.

## TG-f — Intake export filtered by state (no new dependency)
- [ ] Export function for intake events: `done` gives one MedicationAdministration (`completed`) and one DRUG_EXPOSURE row via the M03 mapping; `partial` gives one DRUG_EXPOSURE row and, if emitted, a `stopped` administration; both rows are dated from the intake event and `quantity` is the amount the user entered on that event, else empty, never the planned dose (Q152); the adherence state lives in the administration status, not in DRUG_EXPOSURE columns (Q155); `skipped`, `missed` and stateless events give no DRUG_EXPOSURE row (a MedicationAdministration, if emitted, is `not-done`); no state is guessed; nothing else is exported (Q147). Each scenario below needs a test that asserts the absence of a row for a non-done state. Amend `docs/omop/drug-exposure-mapping.md` with the intake-event rules (Q152). FHIR is hand-written against the R4 spec and is blocked by Q55 for licence; the OMOP part is not. Req: M04 daily-log "Intake events export only what was taken". Scenarios: `daily-log-and-adherence::a-done-intake-exports-one-administration-and-one-exposure`, `daily-log-and-adherence::a-skipped-or-missed-intake-writes-no-exposure`, `daily-log-and-adherence::each-event-is-dated-by-its-own-day`, `daily-log-and-adherence::a-partial-intake-with-an-entered-amount-exports-that-amount`, `daily-log-and-adherence::a-partial-intake-without-an-entered-amount-exports-an-empty-quantity`, `daily-log-and-adherence::a-state-set-by-a-rule-exports-no-exposure`, `daily-log-and-adherence::an-event-without-a-recorded-state-exports-nothing`, `daily-log-and-adherence::an-entered-amount-in-a-different-unit-exports-an-empty-quantity`, `daily-log-and-adherence::an-entered-per-weight-amount-exports-an-empty-quantity`, `daily-log-and-adherence::other-logs-are-not-exported-by-this-change`. Depends on: TG-b, M03 `backend/protocols/omop.py`. Blockers: Q150, Q151, Q152, Q155.
