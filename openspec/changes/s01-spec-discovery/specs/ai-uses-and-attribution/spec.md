## ADDED Requirements

### Requirement: LLM usage is capped by a monthly credit allowance
The system SHALL meter LLM-backed analyses per user against a visible allowance that regenerates monthly, and SHALL NOT place an LLM call in the interactive path of an ordinary page load. (Source: docs/hackingbiology-project-spec.md § 8.4, § 8.5bis. The source gives no amounts; see QUESTIONS.md Q19.)

#### Scenario: Allowance is visible and enforced
- **WHEN** a user requests an LLM-backed analysis
- **THEN** the remaining allowance is shown before and after
- **AND** when it is exhausted the request is declined with the date it regenerates

#### Scenario: Ordinary pages make no LLM call
- **WHEN** an ordinary page is loaded
- **THEN** any narration shown comes from cache, and no LLM call is made

### Requirement: AI proposals are offered as a block
The system SHALL present AI-generated proposals as a block that the user can accept in full or reject in full, and SHALL NOT apply a proposal without that choice. (Source: docs/hackingbiology-project-spec.md § 8.5ter, § 8.4 item 2.)

#### Scenario: Accept all or reject all
- **WHEN** the system proposes changes
- **THEN** the user can accept all or reject all
- **AND** nothing is applied before the user chooses

### Requirement: AI verdict shape with insufficient-data state
The system SHALL present every AI-written verdict as a coloured status (green, yellow, red, or grey for insufficient data), a short tip of at most 18 words, a detail of one to four sentences written by the model around numbers that code inserts from the user's own data, and a regenerate control. A verdict SHALL be cached against a fingerprint of its input data and, when the data changed, SHALL offer regeneration instead of regenerating silently. (Source: docs/getbased-reuse-analysis.md § B2, § B3.)

#### Scenario: Verdict is complete
- **WHEN** a verdict is shown
- **THEN** it has a status colour, a tip of at most 18 words and a detail that refers to the user's numbers
- **AND** every number in the detail is inserted by code, not generated by the model
- **AND** its status is computed by code, not by the model

#### Scenario: Insufficient data is grey
- **WHEN** the data is insufficient to judge
- **THEN** the verdict is grey and states what is missing, and no other colour is shown

#### Scenario: Data changed
- **WHEN** the underlying data changed since the verdict was generated
- **THEN** the verdict says the setup changed and offers regeneration
- **AND** no model call happens until the user asks

### Requirement: Choice of AI provider including a local model
The system SHALL let the user choose the provider of AI-written words, including a model running on their own machine and a user-supplied endpoint, and SHALL make clear which data leaves the user's machine for each choice. (Source: docs/getbased-reuse-analysis.md § B9. The source counts six providers without naming them; see QUESTIONS.md Q28.)

#### Scenario: Local model selected
- **WHEN** the user selects a local model
- **THEN** the call is made from the user's own browser to the local model, and no data is sent to any external AI provider or to the server for this purpose

#### Scenario: User-supplied endpoint
- **WHEN** the user supplies an endpoint
- **THEN** the system uses it for AI-written words only and says what it will send
- **AND** the call to a local or user-supplied endpoint is made from the user's own browser, not from the server
- **AND** if a server-side call to a user-supplied endpoint is ever offered, the server refuses private, loopback and link-local addresses and requires HTTPS; see QUESTIONS.md Q32

#### Scenario: Numbers unaffected by the provider
- **WHEN** the provider is changed
- **THEN** every number shown is unchanged, because numbers are computed by code
